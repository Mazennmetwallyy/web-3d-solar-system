Deeper Understanding

Statement

The project extends the laboratory tutorials in several deliberate directions, each chosen to move beyond what was covered in the labs rather than to repeat it.

Custom GLSL Shaders

The planet surfaces, the Sun, and the atmospheric layers use custom vertex and fragment shaders written in GLSL rather than relying on the default Three.js materials. This was used to produce a more believable Sun with surface noise and a controlled fresnel-style atmospheric rim for Earth-like planets. Writing the shaders meant working directly with uniforms, varyings, and the rendering pipeline, which is well beyond the standard MeshStandardMaterial coverage in the labs.

Post-Processing Pipeline

The final image is composited through an EffectComposer with a RenderPass and a tuned UnrealBloomPass. This gives the Sun and the brighter atmospheres a stylised glow that is consistent with the chosen aesthetic. Balancing the bloom threshold, strength, and radius against the renderer's tone mapping and exposure was one of the longest tuning efforts in the project.

PHP Backend with a JSON API

Planet metadata is served from a small PHP backend that follows a model / controller split. A Planet model class encapsulates the data, and api.php exposes a simple action-based REST-style endpoint returning JSON. This goes beyond the procedural PHP shown in the lab work and provides an honest, self-built API for the front end to consume.

Blender Workflow and Procedural Build

Rather than hand-placing every planet, a Python script (models/build_solar_system.py) drives Blender to construct the scene, and a second script (generate_x3d.py) emits the individual X3D model files. This made it possible to iterate on scale, spacing, and material parameters quickly, and to keep the Three.js and X3D versions of each model in sync.

Dual Web 3D Formats

The application uses Three.js for the live interactive scene, while a parallel set of X3D files is provided under models/x3d/ for each planet. This satisfies both routes offered by the brief and demonstrates the underlying geometry independently of the runtime.

Testing

Feedback from testing and the impact on the site

Testing was carried out across the development cycle and the feedback materially changed the final build. The most useful findings are summarised below.

Loading screen hanging without a server

Opening index.html from the file system caused the loading screen to hang because module imports and texture fetches require an HTTP context. The fix was to expose a clear loading state and to document in the About page that the app must be served over HTTP. The ITS deployment was confirmed to load correctly end-to-end.

Bloom intensity and exposure

Early bloom settings were visually dominant and washed out the planets. Iterative testing against the target aesthetic led to lowered bloom strength, a higher threshold, and a corrected renderer exposure, so that the Sun reads as bright without flooding the rest of the scene.

Alpha compounding on atmospheres

Layered transparent shells were compounding their alpha and producing visibly banded edges. The fix was to adjust blending modes and to keep atmospheric shells to a controlled number of layers, which removed the banding without losing the rim effect.

Responsive layout and accessibility

The Bootstrap layout was tested at mobile, tablet, and desktop widths and the navigation, hero, and 3D canvas were adjusted so the canvas keeps a usable aspect ratio on small screens. A skip link, ARIA labels on the navbar and canvas, and visible focus styles were added in response to keyboard-only testing.

Cross-browser checks

The site was checked in current Chrome, Firefox, and Safari. WebGL behaviour was consistent; the only adjustment needed was to make sure the import map and the post-processing add-ons resolved from the CDN in every browser, which they do.
